# Jev PoC：公式QuickStartとデモ（メール緊急性分類CLI）

Jevに興味を持ち、「まず動かしたい」「自分のソフトウェアでどう使うか知りたい」という人に向けた、小さなPythonのサンプル集です。

**問い合わせ文を評価するQuickStart**と、そこから一歩進めた**メールの緊急性を分類するCLI**を用意しています。付属の架空データだけで試せるため、受信箱への接続や実メールの準備は不要です。TypeSafeの公式サンプルを参考にした個人のPoCであり、公式SDK・公式製品ではありません。

## 何ができるか

| プログラム | 入力 | 確認できること | Jevへの接続方法 |
|---|---|---|---|
| [quick_start.py](quick_start.py) | コード内の日本語の問い合わせ文 | 担当部署、不満度、緊急性。Scoreの段階別確率と計算式 | TypeSafe Python SDK |
| [mail_cli.py](mail_cli.py) | JSON形式のメール一覧、または.emlファイル1件 | 緊急・高・通常・対応不要・判断保留への分類、判定理由、各質問の確率 | HTTP APIを直接呼び出す |

QuickStartではJevの回答形式を確認し、メールCLIではその回答をコード上のルールにつなげます。モデルが返す確率と、アプリケーションが決める最終的な動作の関係を、ソースコードで追える構成です。

最初は、環境の準備 → キーなしのプレビュー → QuickStartの実行 → メールの実分類 → 入力や基準の変更、の順に進めると、送るデータと結果の意味を確認しながら試せます。

## 環境を準備する

必要なものはGit、Python 3.12以上、Python環境管理ツールのuvです。実際のJevへの問い合わせには、TypeSafeのアカウントと利用可能なAPIキーも必要です。

uvが入っていない場合は、[uv公式のインストール手順](https://docs.astral.sh/uv/getting-started/installation/)で準備してください。以下のシェル例はmacOS・Linux・WindowsのWSL向けです。

### リポジトリを取得する

```bash
git clone https://github.com/yutomiyashita/jev-poc.git
cd jev-poc
```

すでにクローン済みの場合は、その `jev-poc` フォルダーに移動します。以降のコマンドは、特記がない限りこのフォルダーで実行してください。

### 依存パッケージを準備する

```bash
uv sync --locked
uv run python --version
```

`pyproject.toml` と `uv.lock` に従って `.venv/` が準備されます。Pythonやパッケージが未取得の場合、この段階ではダウンロードのための通信が発生します。主な依存パッケージは、QuickStart用の `typesafe-sdk` と、設定ファイル読み込み用の `python-dotenv` です。

`uv run` を使うため、仮想環境の有効化コマンドを毎回実行する必要はありません。依存関係の準備だけではTypeSafe APIを呼び出しません。

## APIキーなしでプレビューする

まず、付属の架空メール5件を使って、Jevへ何を送るのか確認します。

```bash
uv run python mail_cli.py examples/emails.json --at 2026-11-08T09:00:00+09:00
```

このコマンドは**TypeSafe APIへ送信しません**。APIキーも不要です。メール1件につき1行のJSONが出力され、`mode` が `dry-run` になります。`request` 内で、送信予定のモデル名、評価日時、メール本文、4つの質問を確認できます。分類結果はこの段階では出ません。

読みやすくする場合は、1行ごとのJSONを整形して表示できます。

```bash
uv run python mail_cli.py examples/emails.json --at 2026-11-08T09:00:00+09:00 | uv run python -m json.tool --json-lines
```

付属データには、予約時刻の変更、支払い期限、来月の食事会、緊急と書かれた任意のセール、情報の足りない確認依頼が入っています。これらは入力例であり、正解ラベル付きの精度評価データセットではありません。

`--at` は評価する日時です。付属データの日付に合わせて固定し、「本日」「2時間以内」を比較しやすくしています。自分の現在のメールを扱う場合は、`--at` を省略すると実行環境の現在日時・タイムゾーンを使います。

## APIキーを設定する

[TypeSafeのコンソール](https://console.typesafe.ai/)で利用可能なAPIキーを準備します。発行方法は[公式Quick start](https://docs.typesafe.ai/introduction/quickstart)を参照してください。

`.env` がまだなければ、ひな形から作ります。次のコマンドは既存の `.env` を上書きしません。

```bash
if [ ! -f .env ]; then
  cp .env.example .env
fi
```

手元のエディターで `.env` を開き、次の空欄に自分のキーを設定します。

```dotenv
TYPESAFE_API_KEY=
```

両プログラムとも、スクリプトと同じフォルダーの `.env` を読み込みます。すでに `TYPESAFE_API_KEY` が環境変数として設定されている場合は、環境変数が優先されます。空の環境変数も優先されるため、`.env` の値を使いたい場合はターミナルで `unset TYPESAFE_API_KEY` を実行してください。

`.env` はGitの追跡対象から除外しています。キーをPythonコード、README、Issue、チャットへ記載する必要はありません。メールCLIのプレビューはキーを読み込まず、両プログラムとも実送信時にキーが空ならAPI呼び出し前に終了します。

## QuickStartを動かす

```bash
uv run python quick_start.py
```

**このコマンドは実際にTypeSafe APIへ問い合わせ、API利用料金が発生します。** メールCLIと異なり、`--send` は不要で、プレビューモードはありません。

評価対象は、コード内の「約20分前からAPI連携で500エラーが返り、顧客の注文を処理できない」という日本語の問い合わせ文です。一度の `system_one()` 呼び出しで、次の3つの質問を渡します。

| 質問ID | 型 | 質問の意味 | 出力 |
|---|---|---|---|
| `department` | Choice | どの部署が担当すべきか | 請求・支払い担当、技術担当、営業担当のいずれか |
| `frustration` | Score | 顧客がどの程度不満を感じているか | 0〜2のスコア、各段階の確率、加重平均の計算式 |
| `is_urgent` | Noul | 緊急性や時間的切迫性を伝えているか | その命題を肯定する確率、0〜1 |

### 出力の読み方

以下は**表示を説明するための仮の数値**です。実際の出力値を保証するものではありません。

```text
担当部署：技術担当
顧客の不満度（0〜2）：0.4
各段階に当てはまる確率：
  段階0：冷静に、事実を述べている
    確率：0.6（60.00%）
  段階1：不満はあるが、礼儀正しい
    確率：0.4（40.00%）
  段階2：非常に怒っていて、強い言葉を使っている
    確率：0.0（0.00%）
返された確率から計算した加重平均：0 × 0.6 + 1 × 0.4 + 2 × 0.0 ≈ 0.4
スコアは各段階の番号を確率で重み付けした平均で、不満の割合（%）ではありません。
緊急性があると判定する確率（0〜1）：0.98
```

Scoreの段階番号は、`criteria` リストの先頭から0、1、2と決まります。3項目なので範囲は0〜2です。`score` は各段階番号の確率加重平均であり、上の `0.4` は「不満が40%」や「正解率40%」ではありません。同じ平均でも確率の分布が異なる場合があるため、内訳も表示しています。[公式のScore説明](https://docs.typesafe.ai/primitives/score)

Noulの `0.98` は、「この文章は緊急性を伝えている」という命題が真であるとモデルが推定した確率です。緊急さの強さ98点を表すものではありません。文面が冷静でも、状況が切迫していることはあるため、不満度と緊急性は独立した観点として尋ねています。[公式のNoul説明](https://docs.typesafe.ai/primitives/noul)

### コードを読む順序

1. `ticket`：今回評価する問い合わせ文。
2. `state=ticket`：評価対象をJevへ渡す部分。
3. `questions`：担当部署、不満度、緊急性の質問をまとめた辞書。
4. `instructions`：何を判定するかを記述する質問文。
5. `criteria`：Choiceの候補、Scoreの段階ごとの説明。
6. `response` と末尾の表示処理：返された結果を取り出して表示する部分。

`state` には文章だけでなく、判断に必要な関連情報を辞書やリストでまとめられます。`questions` はその情報について何を判定するかを指定します。今回の質問IDは開発者が付けた名前で、結果の取得に使います。[公式のState説明](https://docs.typesafe.ai/concepts/state)

このサンプルはChoice・Score・Noulを使います。画像中の位置を扱うBoxは実装していません。

## メールを実際に分類する

プレビューの内容を確認し、APIキーを設定したら、同じコマンドに `--send` を追加します。

```bash
uv run python mail_cli.py examples/emails.json --at 2026-11-08T09:00:00+09:00 --send
```

**この操作はメールの内容をTypeSafe APIへ送り、API利用料金が発生します。** メール1件につき1リクエスト、各リクエストに4つの質問をまとめます。付属サンプルは5件なので、すべて処理した場合は5リクエストです。このCLIに自動再試行はありません。

出力は1行1メールのJSONです。

| フィールド | 内容 |
|---|---|
| `id`、`subject` | 入力メールの識別子と件名 |
| `label` | 緊急・高・通常・対応不要・判断保留 |
| `reason` | コードの分類ルールに対応する説明。Jevが生成した自由記述の理由ではない |
| `probabilities` | 4つのNoul質問それぞれの確率 |
| `model` | APIが返した実際のモデル名 |
| `evaluated_at` | 評価に使用した日時 |
| `usage` | APIが返した利用量情報。料金額そのものではない |

結果を保存したい場合は、リダイレクトできます。次のコマンドもAPIへ送信します。`>` は同名ファイルを上書きするため、残したい結果には別名を付けてください。

```bash
uv run python mail_cli.py examples/emails.json --at 2026-11-08T09:00:00+09:00 --send > results-demo.json
```

このファイルは1行ごとのJSON、いわゆるJSON Lines形式です。`results*.json` はGitの除外対象です。

### 指定できるオプション

```bash
uv run python mail_cli.py --help
```

| 引数・オプション | 既定値 | 用途 |
|---|---|---|
| `input` | 必須 | JSON配列または.emlファイルのパス |
| `--send` | なし | TypeSafe APIへ実送信する。省略時はプレビュー |
| `--at` | 実行時の現在日時 | `2026-11-08T09:00:00+09:00` のようなタイムゾーン付き日時 |
| `--limit` | `10` | 処理する件数の上限。超過した場合は先頭だけを処理せず、送信前に停止 |
| `--model` | `jev-latest` | 使用するモデル名 |

`jev-latest` は更新され得るため、比較実験では入力・評価日時・質問・APIが返したモデル名を記録してください。固定できるモデル名は[公式のモデル一覧](https://docs.typesafe.ai/go/models.md)で確認してください。QuickStartのモデルは `quick_start.py` の `TypeSafeClient(model=...)` で指定します。

## 自分のメールを入力する

### JSON形式

```bash
mkdir -p private
```

手元のエディターで `private/emails.json` を作り、次の形式で保存します。以下は架空の例です。

```json
[
  {
    "id": "mail-001",
    "subject": "予約確認のお願い",
    "date": "2026-11-08T08:00:00+09:00",
    "body": "本日の予約について、10時までに返信をお願いします。"
  }
]
```

| 項目 | 必須 | 指定方法 |
|---|---|---|
| `body` | はい | 空でない文字列。本文20,000文字まで |
| `id` | いいえ | 文字列。省略時は1から始まる番号を文字列で付与 |
| `subject` | いいえ | 件名の文字列。省略時は空文字列 |
| `date` | いいえ | メール日時の文字列。相対的な期限を判断しやすいよう、分かればタイムゾーン付きで記載 |

JSONの最上位は1件以上を含む配列にします。メール日時の解釈はモデルに委ねるため、曖昧な表記は避けてください。

まずプレビューし、内容を確認してから実送信します。

```bash
uv run python mail_cli.py private/emails.json
```

```bash
uv run python mail_cli.py private/emails.json --send
```

### .eml形式

メールアプリでメールを1件書き出し、`private/message.eml` として保存した場合の例です。

```bash
uv run python mail_cli.py private/message.eml
```

実送信する場合だけ `--send` を付けます。

```bash
uv run python mail_cli.py private/message.eml --send
```

本文はプレーンテキストを優先します。HTMLしかない場合はタグを除いて文字列化し、script・styleの内容は除外します。レイアウトを完全に再現する変換ではありません。画像や添付ファイルの中身は評価しません。本文が20,000文字を超える場合は自動で切り捨てず、エラーになります。

### 送信されるデータ

メールCLIが送るのは、件名、メール日時、本文、評価日時、質問・判定基準、指定したモデル名です。入力の `id`、From・Toなどのアドレスヘッダー、添付ファイルは送信ペイロードに含めません。

ただし、**本文や件名に含まれる氏名・住所・引用文などはそのまま送信**されます。JSONに入れた情報は自動で匿名化されません。まず架空データで試し、実メールを使う場合は送信する内容を確認してください。APIキーは認証ヘッダーで使います。

このCLIは受信箱へ接続せず、Gmail連携、メールの移動・削除・返信も行いません。

## メールの分類ルールを読む

質問・基準・閾値・分類ロジックは [policy.py](policy.py) にまとめています。質問文は英語で定義し、日本語のサンプルメールを渡す構成です。

| 質問ID | 判定すること |
|---|---|
| `action_needed` | 受信者に未対応の行動が必要か |
| `immediate` | その対応が評価日時から2時間以内に必要か |
| `today` | その対応が評価日中に必要か |
| `serious_impact` | 対応を遅らせると大きな不利益が生じるか |

各質問のNoulを、コードで `0.7以上＝はい`、`0.3以下＝いいえ`、その間を曖昧と扱います。以下は実装の判定順です。

| 順序 | 条件 | 分類 |
|---|---|---|
| 1 | 対応の必要性が「いいえ」だが、ほかのいずれかが「はい」 | 判断保留 |
| 2 | 対応の必要性が「いいえ」で、ほかに「はい」がない | 対応不要 |
| 3 | 対応の必要性が曖昧 | 判断保留 |
| 4 | 対応が必要で、2時間以内の対応が「はい」 | 緊急 |
| 5 | 対応が必要で、今日中または大きな不利益が「はい」 | 高 |
| 6 | 対応が必要で、上の緊急・高に該当せず、期限や影響に曖昧な回答が残る | 判断保留 |
| 7 | 対応が必要で、期限や影響の3問がすべて「いいえ」 | 通常 |

一つの曖昧な回答ですべてを保留にする実装ではありません。たとえば2時間以内の対応が明確に必要なら、ほかの回答が曖昧でも「緊急」になります。

閾値は実装上の初期値です。業務で使う場合は、人が付けた正解ラベルと比べて、見逃しや過剰な通知を確認する必要があります。メール内の主張の真偽や送信元の真正性は検証しないため、分類だけを根拠に支払いやリンクの操作を自動化する用途にはしていません。

## 自分の用途へ変更する

| 変えたいこと | 変更する場所 | 確認すること |
|---|---|---|
| 別の問い合わせ文を評価する | `quick_start.py` の `ticket` | 担当部署・不満度・緊急性がどう変わるか |
| 担当部署を増やす | Choiceの `criteria` と `department_labels` | 選択肢の意味が重複しないか。表示名も対応させる |
| 不満度の段階を変える | Scoreの `criteria` | 並び順が尺度になる。段階数を変えたら出力の範囲ラベルも更新する |
| 別の性質を確率で判定する | Noulの `instructions` | 「はい／いいえ」で判断できる一つの問いになっているか |
| メールの判断基準を変える | `policy.py` の `QUESTIONS`、`YES`、`NO`、`classify()` | 質問を増減したら分類処理とテストも合わせる |
| 比較するメールを増やす | 自分のJSONデータ | 送信件数、評価日時、本人が期待する分類を揃える |

モデルへの質問と、回答をどう扱うかというコード上のルールを分けて変更すると、どこで結果が変わったのかを追いやすくなります。TypeSafeのエージェントスキルは[公式の案内](https://docs.typesafe.ai/introduction/quickstart)から利用できますが、このリポジトリの実行にスキルのインストールは不要です。

## よくあるつまずき

| 症状 | 確認・対応 |
|---|---|
| `uv` が見つからない | uvをインストールし、ターミナルを開き直して `uv --version` を確認する |
| `ModuleNotFoundError` | `jev-poc` で `uv sync --locked` を実行し、`python` 単体ではなく `uv run python ...` を使う |
| APIキー未設定のメッセージが出る | `.env` のファイル名・保存先・空欄を確認する。空の環境変数が優先されていないかも確認する |
| 認証エラーやHTTP 401が返る | コンソールでキーの有効性を確認し、`.env` と優先される環境変数を確認する。キーの値をログへ出さない |
| HTTP 429や接続エラー | 提供元の利用制限や接続状況を確認する。メールCLIは自動再試行しない |
| プレビューしか出ない | メールCLIは既定がプレビュー。送信内容を確認してから `--send` を付ける |
| 件数上限のエラー | 既定の上限は10件。入力を減らすか、送信量を確認したうえで `--limit` を変更する |
| `--at` のエラー | `2026-11-08T09:00:00+09:00` のようにタイムゾーンを付ける |
| ファイルが見つからない | 入力パスは現在の作業ディレクトリ基準。リポジトリ直下で実行するか絶対パスを指定する |
| 同じ例でも数値が違う | 文言、日時、モデル名を確認する。掲載例の数値との完全一致を成功条件にしない |

メールCLIはAPIエラーや不正な応答を標準エラー出力と終了コード1で通知し、エラーを「対応不要」などの分類には変換しません。途中で失敗した場合、それ以前の結果は標準出力に残り、それ以降は処理しません。保存ファイルが存在しても、全件成功したとは限りません。

## テストと検証状況

ローカルテストはAPIキーなしで実行できます。TypeSafe APIへ実送信せず、モックを使います。

```bash
uv run python -m unittest -v
```

2026-11-08時点の確認範囲：

| 対象 | 確認済み | 未確認・範囲外 |
|---|---|---|
| QuickStart | 利用者による英語版・日本語版のAPI実行結果を確認。環境変数優先・キー未設定時の停止・Score内訳表示はローカルのモックで確認 | 多数の入力に対する精度、Score内訳表示追加後の実API結果、料金の実測 |
| メールCLI | 8件の自動テストに成功。.env読み込み、分類と境界、不正な確率、.emlの抽出、プレビューの通信抑止、モック分類、API失敗時、送信前の件数制限 | 実APIでの分類結果・正解率・閾値の妥当性、実メールでの運用 |

自動テストの成功は、コードがテストで指定した条件を満たすことの確認です。Jevの分類精度を測定したものではありません。実装とローカル検証は、利用者の依頼を受けたAIが担当しています。

## ファイル構成

```text
jev-poc/
├── README.md              # 使い方と結果の読み方
├── .env.example           # APIキー設定のひな形（値は空欄）
├── .gitignore             # 非公開情報・ローカル生成物の除外
├── pyproject.toml         # Python条件と依存パッケージ
├── uv.lock                # 依存バージョンの固定
├── quick_start.py         # SDKでChoice・Score・Noulを試す
├── mail_cli.py            # メールの読み取り・送信・結果表示
├── policy.py              # 4つの質問と分類ロジック
├── test_mail_cli.py       # メールCLIのローカルテスト
└── examples/
    └── emails.json        # 架空のメール5件
```

ローカルで作る `.env`、`.venv/`、`__pycache__/`、`private/`、`*.eml`、`results*.json`、`.agents/` はGitの追跡対象から除外しています。独自に別名で作ったデータファイルまで自動で除外されるわけではないため、個人の入力データは `private/` に置いてください。
